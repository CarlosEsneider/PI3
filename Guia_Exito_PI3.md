# Guía para la Calificación Máxima en el Proyecto Integrador 3 (PI3) 🚀

Esta guía consolida los requerimientos de la **Guía PI Tercero** y los criterios de evaluación de las **Rúbricas PI 3 Semestre** para asegurar que tu equipo obtenga la nota máxima (5.0) en la sustentación final.

---

## 1. Checklist de Entregables Técnicos (Soporte de la Sustentación) 📋
Antes de presentarte, asegúrate de que los siguientes componentes estén impecables, ya que son la base de la demostración funcional.

### Programación (Java)
- [ ] **SCE2.1 Diagramas IPO:** Un diagrama de Entrada-Proceso-Salida por cada método principal.
- [ ] **SCE2.2 Diagrama de Clases:** Debe incluir atributos, métodos y relaciones actualizadas.
- [ ] **SCE2.3 Implementación:** Código limpio, documentado y siguiendo el estándar de capas (Datos, Lógica, Presentación).
- [ ] **SCE2.8 CRUDs:** Todas las funcionalidades básicas (Crear, Leer, Actualizar, Eliminar) deben funcionar sin errores.

### Bases de Datos (SQL)
- [ ] **SCE2.4 Modelo Entidad-Relación (DER):** Estructura lógica correcta.
- [ ] **SCE2.5 Diagrama de Datos:** Representación física de la base de datos.
- [ ] **SCE2.6 Implementación SQL:** Script de creación y al menos **10 registros de prueba** por tabla (según la guía).

### Documentación y Diseño
- [ ] **SCE2.7 Mockups:** Prototipos visuales que coincidan con la aplicación real.
- [ ] **SCE2.9 Normas APA:** Todo el documento final debe seguir estrictamente el formato APA.

---

## 2. Pilares de la Rúbrica SCE2 (Requisitos Técnicos Detallados) 🏗️
Para asegurar el 5.0 en la parte técnica, cada componente debe cumplir con los siguientes criterios de "Excelencia":

### 📊 SCE2.1 Diagramas IPO (Entrada-Proceso-Salida)
*   **Detalle:** Un diagrama por **cada método**.
*   **Claridad:** Flujos de entrada, procesos internos y salidas perfectamente representados.
*   **Lógica:** Explicación detallada de la transformación de datos y la lógica de negocio.

### 📐 SCE2.2 Diagrama de Clases
*   **Precisión:** Tipos de datos correctos para cada atributo.
*   **Documentación:** Métodos claramente definidos y documentados.
*   **Relaciones:** Cardinalidades y tipos de relación (asociación, herencia, etc.) correctos.

### ☕ SCE2.3 Implementación en Java
*   **Optimización:** Código funcional, limpio y eficiente.
*   **Fidelidad:** Implementación exacta de todos los métodos diseñados en los diagramas.
*   **Git:** Repositorio Git activo y bien organizado.

### 🗄️ SCE2.4 y SCE2.5 Modelado de Datos (DER y Datos)
*   **Semántica:** Entidades y relaciones definidas con claridad semántica.
*   **Integridad:** Claves primarias (PK) y foráneas (FK) claramente identificadas.
*   **Normalización:** Estructura de base de datos optimizada y sin redundancias innecesarias.

### 💻 SCE2.6 Implementación SQL
*   **Estructura:** Scripts completos con restricciones (constraints), índices y claves correctamente definidos.
*   **Pruebas:** Scripts probados, optimizados y listos para ejecución.

### 🖼️ SCE2.7 Prototipos (Mockups)
*   **Fidelidad:** Deben cumplir al 100% con los requerimientos del usuario.
*   **UX/UI:** Alta usabilidad, interfaz intuitiva y diseño profesional/atractivo.

### 🔄 SCE2.8 CRUDs
*   **Funcionalidad:** Operaciones Completas (Create, Read, Update, Delete) implementadas y funcionales.
*   **Interfaz:** Deben ser fáciles de usar y estar integradas con la base de datos.

### 📖 SCE2.9 Normas APA
*   **Formato:** Cumplimiento total (márgenes, fuentes, interlineado, encabezados).
*   **Citas:** Mínimo **5 citas y referencias** formateadas correctamente.
*   **Redacción:** Lenguaje académico y estructura coherente.

## 3. Pilares de la Sustentación Final (Rúbrica SCE3) 💎
Para sacar 5.0, debes cumplir con el nivel "Excelente" en cada uno de estos puntos:

### 🗣️ SCE3.1 Claridad en la Exposición
*   **Estructura:** Inicia con una introducción (quiénes son, qué problema resuelven), sigue con la solución técnica y termina con conclusiones.
*   **Fluidez:** No lean diapositivas. Usen apoyos visuales (diagramas, mockups) para explicar ideas complejas.

### 💻 SCE3.2 Uso de Lenguaje Técnico
*   **Precisión:** Usen términos correctos como: *"Programación Orientada a Objetos", "Herencia", "Polimorfismo", "Normalización de base de datos", "Persistencia", "Patrón DAO"* o *"Capas de arquitectura"*.

### 👔 SCE3.3 Presentación Personal y Actitud
*   **Imagen:** Vestimenta acorde al contexto profesional (semi-formal o formal).
*   **Actitud:** Mantengan contacto visual con el jurado/profesor. Muestren seguridad y respeto.

### 🚀 SCE3.4 Demostración Funcional (Punto Crítico)
*   **Cero Errores:** Realicen pruebas previas. Nada baja más la nota que un error en vivo.
*   **Interactividad:** Muestren cómo el sistema responde a diferentes entradas (validaciones, mensajes de éxito/error).
*   **Fluidez:** La navegación entre pantallas debe ser rápida y lógica.

### 📝 SCE3.5 Conclusiones Derivadas
*   **Impacto:** Expliquen cómo el software resuelve el problema planteado inicialmente.
*   **Aprendizaje:** Mencionen qué retos técnicos superaron y qué recomiendan para futuras versiones (escalabilidad).

### 🤝 SCE3.6 Trabajo en Equipo
*   **Coordinación:** Todos deben hablar y conocer todas las áreas del proyecto. Si alguien hace una pregunta técnica de base de datos a quien hizo la UI, este debe ser capaz de responder o complementar.
*   **Cohesión:** Eviten contradicciones entre miembros.

---

## 4. Consejos de "Oro" para el Éxito 💡

1.  **El "Happy Path" y Casos de Borde:** Durante la demo, primero muestren el flujo que funciona perfecto (Happy Path). Luego, demuestren que el sistema es robusto validando que no permite campos vacíos o tipos de datos incorrectos.
2.  **Preparación de Datos:** Tengan los 10 registros de prueba ya cargados para que los reportes y tablas no se vean vacíos.
3.  **Manejo de Pregunas:** Si no saben algo, no inventen. Es mejor decir: *"Esa funcionalidad está contemplada para la siguiente fase de escalabilidad..."* o *"Lo manejamos a través de la capa de [X] para asegurar la integridad..."*.
4.  **Entorno Listo:** Asegúrense de que el motor de base de datos (SQLite/MySQL) esté corriendo y las librerías de Java estén correctamente vinculadas antes de que empiece su turno.
